7. Two Sets II: Three Formulations

The same counting problem represented by three different state semantics

Fixed identities, sorted sums, and current/other roles give three coordinate systems for the same count. The subtrees compare how choices change those coordinates.

Problem statement, counting convention, and examples

Problem. Count the ways to divide the integers 1,2,…,n into two sets having equal sum. The two final sets are unordered.

Example 1 (used throughout). n=7, total 28, target per set 14. There are 4 unordered equal-sum partitions, so the displayed recursions return 8 labeled assignments before the final division by 2.

Example 2. n=4→1, represented by {1,4}∣{2,3}.

Example 3. n=5→0, because the total is odd.

Each state records the next integer i and two sums. The code below assumes even total sum; odd totals have answer 0. Each unordered partition has two labeled assignments, hence division by 2. The CSES problem uses modulus 109+7; these small examples use exact counts.

Two concrete histories viewed through three coordinate systems

The membership line above a node records the actual sets. The circle records only the parameters received by that recursive call.

Why the three recursive programs return the same count

Fixed-set symmetry. Exchanging Set 1 and Set 2 leaves the terminal test and the pair of recursive choices unchanged, so F(i,a,b)=F(i,b,a).

Canonical coordinates. G evaluates the same two assignments as F, but rewrites each child in larger/smaller order. This changes the state labels and can make two separate calls have equal arguments; both branch contributions remain present.

Dynamic coordinates. H keeps the first coordinate attached to the most recently selected role. Its second branch calls H(i+1,O+i,C); applying the symmetry of F shows that this reordered call has the same continuation count as the corresponding fixed-set call.

The counts agree; coordinate normalization does not remove either branch's contribution.

Recursive code: fixed Set 1 and Set 2

The two sum positions have permanent identities. Sending an integer to one set never changes the interpretation of either parameter.

N = 7
TARGET = N * (N + 1) // 4

def count_fixed(i, set1_sum, set2_sum):
    # Base cases
    if set1_sum > TARGET or set2_sum > TARGET:
        return 0
    if i > N:
        return int(set1_sum == TARGET and
                   set2_sum == TARGET)

    # Choice 1: send i to permanently named Set 1.
    send_set1 = count_fixed(
        i + 1, set1_sum + i, set2_sum)

    # Choice 2: send i to permanently named Set 2.
    send_set2 = count_fixed(
        i + 1, set1_sum, set2_sum + i)

    return send_set1 + send_set2

answer = count_fixed(1, 0, 0) // 2

Invariant: parameter identity is permanent

a is always the sum of Set 1 and b is always the sum of Set 2. The relation F(i,a,b)=F(i,b,a) is mathematically valid, but this formulation does not use it to rename or merge calls.

Consequently, F(3,1,2) and F(3,2,1) are symmetric but distinct recursive calls. The membership labels remain attached to the same named sets.

Selected subtree: memberships stay attached to A and B

Gold traces 1→A, 2→B, 3→A. Set membership and parameter identity agree throughout.

Recursive code: normalize both children

Each choice adds to a role, then sorts the two resulting sums. The actual sets keep their elements while their L/S names may change.

N = 7
TARGET = N * (N + 1) // 4

def normalize(x, y):
    return max(x, y), min(x, y)

def count_large_small(i, large, small):
    # Base cases
    if large > TARGET:
        return 0
    if i > N:
        return int(large == TARGET and
                   small == TARGET)

    # Choice 1: add i to the set currently called L.
    next_large, next_small = normalize(large + i, small)
    send_large = count_large_small(
        i + 1, next_large, next_small)

    # Choice 2: add i to the set currently called S.
    next_large, next_small = normalize(large, small + i)
    send_small = count_large_small(
        i + 1, next_large, next_small)

    return send_large + send_small

answer = count_large_small(1, 0, 0) // 2

Invariant: numerical order, not set identity

L≥S at every call. If adding i to the smaller sum makes it larger, the next call interchanges the two coordinate roles.

At the root, “put 1 in L” and “put 1 in S, then normalize” both call G(2,1,0). The plain recursion evaluates both calls; their two contributions must still be added.

Selected subtree: normalization can interchange L and S

The two root children are drawn separately because there is no memoization; the equality annotation records multiplicity, not merging.

Recursive code: the recipient becomes current

Choosing current preserves the roles. Choosing other adds i to O and passes that recipient first in the next recursive call.

N = 7
TARGET = N * (N + 1) // 4

def count_current_other(i, current, other):
    # Base cases
    if current > TARGET or other > TARGET:
        return 0
    if i > N:
        return int(current == TARGET and
                   other == TARGET)

    # Choice 1: current receives i and keeps its role.
    send_current = count_current_other(
        i + 1, current + i, other)

    # Choice 2: other receives i and becomes current.
    send_other = count_current_other(
        i + 1, other + i, current)

    return send_current + send_other

answer = count_current_other(1, 0, 0) // 2

Invariant: role follows the action, not magnitude

The second branch is H(i+1,O+i,C): the recipient becomes current and the old current becomes other. No sorting occurs.

Therefore C may be less than O. This distinguishes H from G even when a short history happens to produce the same numeric tuple. Equal root arguments again remain two recursive calls.

Selected subtree: choosing other explicitly rotates the roles

The lower contrast branch shows H(5,4,6): current is smaller, which cannot occur in the canonical large/small formulation.

Reading the same choices across F, G, and H

Along history H, the physical assignment is always A={1,3} and B={2}. The diagrams differ only in how the current call names these sets.

Form final key first coordinate means why a role changes
F (4,4,2) permanently named A never changes
G (4,4,2) currently larger set normalize whenever order reverses
H (4,4,2) recipient designated current choosing other rotates roles

The equal numeric keys at the end of this one history do not make the formulations identical. History K separates them immediately: F(5,6,4), G(5,6,4), but H(5,4,6) with C<O.

Repeated calls are deliberately drawn twice. The dotted equality annotation means “same arguments and two additive contributions,” not a cache lookup or a merged memoization node.
