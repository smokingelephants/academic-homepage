About this handbook

This handbook connects recursive programs, state graphs, and dynamic programming tables through small, fully specified examples. It assumes familiarity with Python, recursion, and basic graph algorithms. Brief captions identify the dependencies, evaluation order, and choices visible in each snapshot.

Fibonacci introduces repeated subproblems; knapsack and edit distance compare alternatives; matrix-chain multiplication combines two required subproblems per choice. Water jugs and Hanoi expose cycles and shortest-path structure. Two Sets II closes with three recursive coordinate systems for the same counting problem.

How to read the diagrams

  • Calls and states. Repeated arguments give separate occurrences in a call tree and a single vertex in a merged state graph.

  • Forward arrows are calls or dependencies. Faint or dotted edges are pending or contextual; stronger edges are currently active.

  • Return labels complete an expression. A placeholder such as value + ?? becomes value + returned value when its child finishes.

  • Emphasis follows the chapter legend. Gold usually marks an optimal choice; in Fibonacci it marks a memoization frontier, and in Two Sets II it marks a comparison history.

  • Black partition nodes join required calls. In matrix-chain multiplication they show that one split needs both interval subproblems.

  • Table order follows dependencies. Blank cells await evaluation; disabled cells lie outside the recurrence's state space. Some valid table cells are absent from the selected recursive trace.

Acyclic versus cyclic dependencies. Memoization reuses a completed value; a visited mark only rejects a cycle on the current path. In the jug and Hanoi graphs, distance-to-target labels describe unrestricted shortest paths. A recursive call under an existing visited set may have fewer admissible continuations.

Diagrams retain the original vector artwork. Select a diagram to open it at full size; text, code, and tables are available directly on these pages.
